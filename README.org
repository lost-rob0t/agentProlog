* The agent application on Prolog-RLM

AgentProlog composes a reusable Prolog-RLM runtime into a configurable agent
application. This repository owns product configuration, coding tools, session
hosting, scripting clients and presentation adapters. Execution semantics stay
in Prolog-RLM: there is no second provider engine, prompt compiler, scheduler,
authority system or effect ledger here.

#+begin_example
AgentProlog UI / script / integration
  -> canonical session host and frontend protocol
  -> trusted Prolog configuration, tools and hooks
  -> public Prolog-RLM runtime APIs
#+end_example

* Quick start

These commands run the current checkout. Installation from a remote branch does
not make unmerged changes part of an official release.

#+begin_src sh
nix run .#agentProlog -- --help
nix run .#agentProlog -- --project /absolute/project --state /absolute/private/session-state
#+end_src

The terminal client is interactive. An unconfigured session has no granted tools.
Running a model turn requires an explicitly configured and authorized provider.
Use a trusted operator Prolog file for grants, packages, agent selection and
budget policy:

#+begin_src sh
nix run .#agentProlog -- --project /absolute/project --config /absolute/operator.pl
#+end_src

Import Markdown skills into inert native Prolog prompt-unit data:

#+begin_src sh
nix run .#import-skill -- /path/to/skill-package /path/to/native-skill.pl
#+end_src

* Current capabilities

- Prolog operator, plugin and project configuration; named agent profiles with
  narrowing capability/budget inheritance.
- Native Prolog skills, standard Markdown skill import, and explicitly trusted
  ordinary local SWI-Prolog packages.
- Confined file read/create/write/modify tools with content preconditions and
  native per-operation authority. A fixed Node syntax-check tool has no shell.
- Durable project/configuration-bound sessions, snapshots, correlated commands,
  approvals, questions, usage, cancellation and conservative restart recovery.
- A real-model coding acceptance example and independent HTTP CRUD verification.
- Canonical JavaScript client, interactive terminal UI, DeepSeek Harness bridge
  and optional Zara runtime profile.

* Guarantees and limits

Trusted executable Prolog is not sandboxed by tool capability policy. File
confinement is not OS isolation. Skill selection never grants authority. Model
completion is distinct from independent artifact acceptance. Reported model cost
is not a provider-enforced monetary reservation.

The small todo target is in-memory; HTTP behavior and HTML presence are tested,
not a full browser-automation or production-deployment guarantee. Native
skill/system-prompt projection is currently non-streaming. UI, integration and
provider-specific gates must be assessed separately rather than inferred from
one successful demonstration.

The bundled resumable per-tool approval UI supports =direct= mode. Typed-plan
pending approvals in =rlm= mode are not bridged into that same continuation.
