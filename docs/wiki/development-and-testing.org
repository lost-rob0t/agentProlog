* Development environment

Run commands below from the repository root unless a command explicitly changes its working directory. The source of packaging truth is [[file:../../flake.nix][flake.nix]], with dependency resolution in [[file:../../flake.lock][flake.lock]].

#+begin_src sh

These commands may fetch/build Nix dependencies but do not themselves request a model completion. The development shell contains the upstream runtime, Node 22, Python 3 for documentation checks, and the skill importer; it does not list the application/session launcher as additional shell packages. Python is a verification/documentation dependency, not the production agent runtime. Use the packaged application or supply a deliberately constructed local launcher for source-level CLI work.

The runtime input is pinned in =flake.nix= to =4716ba8aa0bbf3fa1b96d80e8ed8e91d99973c85= at the documented source revision. Treat that file and =flake.lock= as authority if the pin changes; historical prose is not a dependency selector. =scripts/check.sh= verifies a supplied local runtime checkout's HEAD against the exact revision in =flake.nix= before running tests. * Recommended deterministic gate

Prerequisites: SWI-Prolog, a compatible Node installation, Python 3, npm (the installed CLI fixture uses local npm installation), and the exact pinned Prolog-RLM checkout. No provider credential is needed.

#+begin_src sh
bash scripts/check.sh /absolute/path/to/pinned/prolog-rlm
#+end_src

[[file:../../scripts/check.sh][The script]] performs:

1. Exact runtime HEAD comparison against =flake.nix=.
2. Org documentation link/provenance checks and Python checker unit tests.
3. Extract the tutorial's two complete Prolog modules and load them through the actual configuration API, without provider calls.
4. Seven Prolog suites using =-p library= pointed at that runtime source.
5. =node --test test/*.test.js= for each JS package: DeepSeek Harness, Zara profile and conversation UI, including scripting examples.
6. Conversation UI =generic.runtime.js= and =native.runtime.js= in actual SWI child processes.
7. Whitespace/error checking with =git diff --check=.

The script does not invoke =downstream.runtime.js=, =live-acceptance.js= or =todo-app-acceptance.js=.

Native is not synonymous with live: a real SWI process and real filesystem can still use deterministic model callbacks. Conversely, a model claiming completion is not acceptance evidence. Read terminal =run.outcome.status=, inspect successful tool outcomes, verify actual file hashes, and independently test generated behavior.

* Downstream integration is opt-in

The downstream lane requires =AGENTPROLOG_HARNESS_ROOT= and =PROLOG_RLM_SOURCE= pointing at exact checkouts from [[file:../../packages/conversation-ui/test/integration-pins.json][integration-pins.json]]. It asserts those HEADs before execution. This is a synthetic compatibility lane, not a request to fetch data or run live research. * Live and recorded acceptance safety

Neither ordinary unit tests nor default PR/push workflows call providers. Live entrypoints fail without their explicit opt-in and existing credential. Authorization for an earlier invocation does not authorize another one. Do not run them merely to make a documentation change green.

The manual filesystem lane uses a fixed upstream Z.AI Coding Plan constructor and model, with no fallback. The todo lane explicitly selects =openrouter= or =zai_coding=; it permits at most three generation/verification-driven turns, retains original requirements for repairs and blocks automatic repair on unknown cost. Runtime =max_cost_usd= and per-invocation accounting are guards based on reported usage, not provider-enforced billing reservations or a cap across separately started invocations.

The independent [[file:../../packages/conversation-ui/test/todo-app-proof.js][todo checker]] syntax-checks =app.mjs= and imports its exported =createServer()= in a separate clean-environment Node process. It checks real loopback HTTP CRUD, validation and other-todo isolation. Node permission flags and heap limits are not an OS/network sandbox. HTML/input/script presence is checked; browser interactions are not automated.

Recorded rechecks make no provider call, but they execute existing generated code and write =evidence.json= in the selected artifact directory. Use only a reviewed isolated artifact. The current recorded verifier deliberately requires the recorded route =openrouter= / =openai/gpt-4.1-mini=; it is not a provider-agnostic evidence importer.

* Known development pitfalls

- =snapshot_required= immediately after connection indicates readiness/handshake problems, not permission to bypass checks. =connect()= must await negotiation plus snapshot; see [[file:../../packages/conversation-ui/test/transport.test.js][transport tests]].
- A new source/configuration binding requires a new state directory or intentionally managed migration; do not delete an operator's old checkpoint to hide a mismatch.
- A completed stream may contain a failed/rejected/interrupted native outcome. Assertions should use =run.outcome.status= and concrete observations, not the word “finished.”
- =workspace_check= reports syntax only. =exit_code:0= does not establish HTTP behavior or task correctness.
- The todo checker uses stable Node =--permission=; obsolete permission flags are not a compatible substitute. Use the supported Node range and positive checker fixture, not just negative tests.
- Configured native skills/system prompts currently use non-streaming model projection. Lack of incremental text there does not imply a second provider loop is needed.

For API signatures, CLI options and trust boundaries, see [[file:api-reference.org][API reference]].
