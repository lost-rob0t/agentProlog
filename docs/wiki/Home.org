runtime. This wiki documents the implementation in this checkout, including
trusted Prolog configuration, named agents, native skills, local packages,
workspace tools, approvals, sessions and programmatic clients.

* A useful reading order

1. Install the pinned toolchain and run the CLI help.
2. Start with no tools or a read-only configuration.
3. Read the trust boundary before loading a Prolog plugin or package.
4. Pick a named agent and configure explicit capability/budget ceilings.
5. Add native skills through the existing compiler, not executable model text.
6. Follow the todo tutorial and independently test the generated application.
7. Use the canonical client for scripting; the terminal CLI is interactive.

* What the application does, and does not promise

- The Prolog-RLM runtime owns model/tool execution, capabilities, authority,
  cancellation, budgets and durable effect semantics. A UI is not another engine.
- Operator and plugin Prolog is explicitly trusted executable code. Native skill
  documents are inert data and do not grant capabilities.
- A completed model turn is not proof that its artifact meets requirements.
  The todo acceptance example checks actual HTTP CRUD behavior separately.
- A runtime USD target is reported-usage accounting, not a guaranteed provider
  billing reservation. A previous manual authorization is not future spend consent.
- The small todo target uses in-memory storage. Its HTTP behavior and HTML page
  are checked; browser interactions and restart persistence are not claimed.
- Native skill/system-instruction projection currently uses non-streaming model
  callbacks. Other turns retain the existing streaming path.
- Local documentation and examples do not imply that these branch changes are
  merged, deployed, publicly published, or production-ready in every environment.
