* Startup and configuration failures

** CLI asks for a launcher or rejects external-adapter flags

Symptom: “Run the packaged Nix application, set AGENTPROLOG_SESSION ...”, or
“project/config flags require the bundled generic host.”

Diagnostic:
#+begin_src sh
node packages/conversation-ui/src/cli.js --help
command -v agentprolog-session
#+end_src

Fix: launch the packaged =nix run . -- --project /absolute/project=, or configure
the existing generic host launcher using =AGENTPROLOG_SESSION=. For an external
adapter use =--sidecar EXECUTABLE --sidecar-arg ARG= and its own contract, not
bundled =--project=, =--state= or config flags. Check whether the launch environment
selects =AGENTPROLOG_SIDECAR= without dumping its contents into logs.

Verified limitation: shell command strings are not accepted as an argv shortcut;
the client uses =spawn(..., shell:false)=. Running the packaged application only
checks launch configuration until a turn is submitted; a turn may call a provider.

Symptom: =duplicate_option=, =duplicate_source=, =module_conflict=,
=reserved_module=, =duplicate_package=, =duplicate_tool_name=, =duplicate_agent=,

Inspect the *reviewed* operator/plugin/pack paths in your own launch as well.
Check overlapping =--config= and CLI single-valued options, repeated plugin/pack
paths, reused module declarations across distinct sources, repeated =name(...)=

Fix: retain one intended declaration/source for each identity, use distinct
module names for distinct files, remove duplicate grants/options and restart
fresh. Give imported skills unique =skill(Name)= identities instead of loading

Verified limitation: tools and =skill_files= are additive across layers. Module
identity is process-global, and failed trusted initialization is not transactional.

* Connection and recovery failures

** Snapshot race, snapshot timeout or sequence gap

Symptom: =snapshot_required= immediately after connect, =snapshot_timeout=,
=sequence_gap=, =session_mismatch= or disconnected/stale display.

Diagnostic:
#+begin_src sh
node --test packages/conversation-ui/test/transport.test.js packages/conversation-ui/test/client.test.js packages/conversation-ui/test/projection.test.js
#+end_src

Fix: =await client.connect()= before commands. Current =connect()= waits for both
negotiation and the canonical snapshot; the formerly observed negotiation-only
readiness race is resolved and has a regression test with a separately delivered
snapshot. A custom adapter must emit the correct snapshot after negotiation and
ordered events thereafter. Reconnect for canonical state after a fault rather
than fabricating missing events or replaying mutations.

Verified limitation: increasing timeouts or adding sleeps does not repair a
malformed protocol. The bundled host returns full snapshots, not event-log replay.
Old visible state is stale and cannot authorize decisions. Reconnect restarts the
child and can interrupt a running native task.

** Owner lock, configuration mismatch or receipt exhaustion

Symptom: lock acquisition/start failure, =session_configuration_mismatch=,
=receipt_limit= or =request_conflict=.

Diagnostic (identifies processes without displaying arbitrary command-line secrets):
#+begin_src sh
lsof -- "$STATE/owner.lock"
#+end_src

To inspect only coarse checkpoint metadata, not objectives/tool payloads:
#+begin_src sh
python3 -c 'import json,sys; s=json.load(open(sys.argv[1])); print({k:s.get(k) for k in ("version","session_id","workspace_id","phase","run_id","config_binding")}); print("receipt_count",len(s.get("receipts",[])))' "$STATE/session.json"
#+end_src

Fix: stop the correct competing owner. Restore the original project/config/source
bytes when resuming the same identity; otherwise deliberately select a new
private =--state= directory. Preserve old state. A repeated wire request ID must
have the same command/payload. An unknown outcome requires inspection, not a new
UUID and blind retry.

Verified limitation: deleting =owner.lock= while a process owns the old inode
does not safely release ownership. There is no session migration, receipt-pruning
or configuration-rebinding CLI. Default state selection hashes the project path,
not the config, so a changed agent/plugin can still select old incompatible state.

** Stale approval, busy session or interrupted resume

Symptom: =stale_decision=, =decision_not_offered=, =invalid_approval=,
=session_busy=, or a reconnect shows interrupted instead of complete.

Diagnostic in the running terminal:
#+begin_example
/inspect
/profile
#+end_example

Fix: use only a currently pending ID and its offered =allow_once= or =deny=.
Wait for actual terminal cancellation/cleanup before a new turn. A native approval
lost on restart has no recoverable in-memory cursor; inspect actual files, then
choose a new objective or =/resume= intentionally. =/resume= reruns the last
objective under a new run ID and can consume new provider usage.

Verified limitation: cancellation is not rollback; command acknowledgement is
not completion. Artifact-only pending reviews can survive an abrupt checkpoint
restore, unlike native pending execution; normal shutdown requests their
cancellation, so do not assume graceful reconnect preserves them. Neither acceptance nor =state.status:"finished"= proves
publication or success; inspect =state.run.outcome.status=.

** Stale source hash, create-on-existing-file or nonunique modify

Symptom: =stale_content=, =already_exists=, =non_unique_match=,
=invalid_path=, =symlink_denied=, =missing_parent= or =file_too_large=.

Diagnostic:
#+begin_src sh

Fix: read the current file and inspect its actual hash, reconcile intervening

preconditions because an older operation was approved.

Verified limitation: preflight and execution revalidation catch normal intervening
changes, not every hostile concurrent filesystem race. These tools do not create
directories/delete files and are not an OS sandbox.

** Missing credential, unknown cost or exhausted acceptance target

Symptom: opt-in acceptance refuses to start, returns sanitized native provider
failure, reports unknown cost, or blocks an automatic repair on budget/cost.

Diagnostic (presence only; never print the value):
#+begin_src sh
node -e 'for (const n of ["OPENROUTER_API_KEY","ZAI_API_KEY"]) console.log(n + ": " + (process.env[n] ? "present" : "missing"))'
#+end_src

Fix: request the operator's existing authorized credential through their normal
secret mechanism and confirm intended provider, model, endpoint, key type and
quota. Do not create accounts, recover secrets, switch to another paid provider
or increase budget without authorization. For the todo runner, explicitly select
=openrouter= or =zai_coding=; it has no automatic fallback. Known cumulative
cost and the per-invocation target govern permitted repairs; unknown cost blocks
additional automatic model turns.

Verified limitation: presence is not validity or proof of billing category.
=max_cost_usd= is a reported-usage guard, not a provider-side reservation. A new
runner invocation starts new accounting; previous permission or the final turn's
cost does not establish cumulative authorization.
